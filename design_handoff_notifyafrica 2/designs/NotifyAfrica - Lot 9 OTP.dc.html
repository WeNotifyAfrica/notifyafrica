Codes à usage unique

L'OTP n'est pas un SMS comme les autres : c'est un service de vérification. NotifyAfrica facture le code vérifié, pas la tentative d'envoi — ce qui aligne le coût sur la valeur et protège le client des échecs opérateur. Le tarif vient du même moteur de prix que les autres canaux.

I · Règles métier

Facturation au code vérifié : un code envoyé mais non vérifié n'est pas facturé. Un renvoi ne crée pas une nouvelle facturation si le code final est vérifié. Le repli sur un autre canal est facturé au tarif de ce canal. Le code n'est jamais stocké en clair. Les limites par numéro et par heure sont configurables par application et bornées par une limite globale définie en back-office.

J · États

Demandé, envoyé, remis, vérifié, expiré, tentatives épuisées, renvoyé, bloqué (anti-fraude), échec opérateur, canal de repli déclenché. Application désactivée. Modèle WhatsApp non approuvé. Pays non couvert. Quota de l'organisation atteint.

L · Cas limites

Deux codes demandés simultanément pour le même numéro : seul le dernier reste valable, les précédents sont invalidés. Code vérifié après expiration : refusé, non facturé. Le repli WhatsApp part alors que le SMS arrive finalement : une seule facturation. Attaque par énumération de numéros : blocage automatique et alerte à l'Admin NotifyAfrica.

N · À valider

Facturer au code vérifié est favorable au client mais expose NotifyAfrica au coût opérateur des codes non vérifiés : faut-il un plancher (par exemple facturer au-delà de 25 % de codes non vérifiés) ? Le client doit-il pouvoir désactiver le repli WhatsApp pour maîtriser son coût ? Faut-il exposer une API de vérification côté serveur uniquement, pour empêcher la vérification depuis le mobile ?
